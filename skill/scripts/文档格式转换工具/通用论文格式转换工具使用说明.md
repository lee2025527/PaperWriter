# 通用论文格式转换工具使用说明

**版本**: 2.0 (Hybrid Mode)
**日期**: 2025-12-24

## 1. 工具简介 (Introduction)

本工具 (`universal_md_to_docx.py`) 是一个**配置驱动**且支持**模板注入**的文档生成系统。它能够将 Markdown 论文内容，结合 JSON 格式规则，精准渲染为 Word 文档。V2 版本新增了“混合驱动模式”，支持直接在学校提供的 Word 模板基础上追加内容，完美解决封面、原创声明等复杂排版问题。

## 2. 核心功能 (Key Features)

1. **配置驱动 (JSON Configuration)**: 字体、字号、边距完全由 JSON 定义，无需修改代码。
2. **模板注入 (Template Injection)**: 支持加载现有 `.docx` 文件（含封面/红头），在末尾智能追加正文。
3. **自动目录 (Auto TOC)**: 识别 Markdown 中的 `[TOC]` 标记，自动转换为 Word 目录域。
4. **混合渲染 (Hybrid Rendering)**: 即使在模板基础上追加，正文格式依然严格遵循 JSON 配置（如强制小四号宋体），不受模板默认样式干扰。

## 3. 标准工作流 (Workflow)

### 场景 A：从零生成 (适用于无模板情况)

直接根据 Markdown 和 JSON 生成纯白 Word 文档。

```bash
python universal_md_to_docx.py input.md output.docx config.json
```

### 场景 B：混合模式 (适用于含封面模板) **[推荐]**

在学校提供的模板（含封面、诚信书）后面追加正文。

```bash
python universal_md_to_docx.py input.md output.docx config.json --template template.docx
```

### 场景 C：交叉引用后处理（Word 原生 REF 交叉引用）

当需要实现“正文引用点击跳转到参考文献”的效果，且必须保持 Word 原生交叉引用机制时，使用独立后处理脚本对已生成的 `.docx` 进行处理：

```bash
python3 add_reference_crossrefs_ref.py input.docx output.docx
```

该脚本仅插入 **REF 字段**与**书签**，不调整任何样式、段落、行距或排版。

## 4. 详细参数说明

| 参数 | 必选 | 说明 | 示例 |
| :--- | :--- | :--- | :--- |
| `input_md` | 是 | 输入的 Markdown 稿件路径 | `论文正文.md` |
| `output_docx` | 是 | 输出的 Word 文档路径 | `交付版.docx` |
| `config_json` | 是 | 样式配置文件路径 | `docx_config.json` |
| `--template` | 否 | 底板模板路径 (.docx) | `template_school.docx` |

### 4.1 交叉引用后处理脚本参数（REF 版）

工具文件：`add_reference_crossrefs_ref.py`

```bash
python3 add_reference_crossrefs_ref.py input.docx output.docx \
  --ref-heading="参考文献" \
  --stop-heading "致谢"
```

参数说明：
- `input.docx`：待处理的 Word 文件（必须包含参考文献段）
- `output.docx`：输出文件路径
- `--ref-heading`：参考文献标题文本（默认 `参考文献`）
- `--stop-heading`：参考文献结束的标题文本，可多次传入（默认包含 `致谢`、`Acknowledgements`、`Acknowledgments`）

---

### 特殊标记说明

在 Markdown 文件中：

* **`[TOC]`**: 独占一行写入此标记，工具会自动在此处插入 Word 目录域代码。
  * *注意*: 生成后需在 Word 中右键“更新域”才能显示页码。
* **`---`**: 强制分页符。

## 5. 配置文件 (JSON) 编写指南

`config.json` 控制正文的所有细节（页面、字体、字号、行距、缩进、标题层级、参考文献样式等）。  
**每个项目都应按客户格式要求生成一份“独属配置”。**

建议做法：**以模板 JSON 为起点，复制后按客户要求逐项修改**（而不是临时手写）。

```json
{
    "page_setup": { "paper_size": "A4", "margin_top_cm": 2.54 }, // 页面设置
    "fonts": { "cjk": "宋体", "latin": "Times New Roman" },       // 全局字体
    "default_style": { "font_size_pt": 12, "line_spacing": 1.5 }, // 正文默认样式
    "styles": {
        "heading_1": { "font_size_pt": 14, "bold": true, "alignment": "CENTER" } // 一级标题样式
    }
}
```

## 5.1 项目复用建议（推荐）

为保证不同项目“看得懂、用得快”，按以下固定流程执行：

1. **复制模板**：`scripts/文档格式转换工具/config_template.json`  
2. **生成项目专属配置**：根据客户格式要求逐项修改  
   - 字体/字号、行距、首行缩进、段前段后  
   - 标题 1/2/3 样式与对齐方式  
   - 参考文献字号与悬挂缩进  
3. **放到项目输出区**：例如 `output/work/docx_config.json`  
4. **调用工具生成 Word**：使用该项目专属 JSON

示例：

```bash
python universal_md_to_docx.py input.md output.docx output/work/docx_config.json
```

> 说明：模板 JSON 只是“起点”，每个项目都需要按客户格式要求生成一份新的 JSON，才能保证排版准确。

## 6. 常见问题 (FAQ)

* **Q: 模板是 .doc 格式怎么办？**
  * A: 本工具仅支持 .docx。请先在 Word 中将 .doc 另存为 .docx 后再使用。
* **Q: 目录显示为 `{TOC ...}` 代码？**
  * A: 这是正常的 Word 域代码。请选中该行，按 `Shift+F9` 切换显示，或右键选择“更新域”。
* **Q: 封面有些错位？**
  * A: 可能是 .doc 转 .docx 时的自然损耗。建议直接编辑 .docx 版本的模板调整一次即可复用。
* **Q: 交叉引用在 Word 里不显示为数字或未跳转？**
  * A: REF 字段需要更新。打开 Word 后按 `Ctrl+A` 选中全文，再按 `F9` 更新域；或右键“更新域”。如果仍不更新，请确认参考文献标题与编号格式为 `^[n]` 开头。

## 7. 交叉引用脚本输入/输出与格式限制

### 7.1 输入格式要求
1. 参考文献标题需为单独一行（默认识别 `参考文献`）。
2. 参考文献条目需以 `[n]` 开头（如 `[15] 作者. 题名[J]. ...`）。
3. 正文引用需为 `[n]` 形式（支持一段中多处出现）。

### 7.2 输出行为
- 在参考文献编号处创建书签 `ref_n`。
- 正文 `[n]` 替换为 Word 原生 `REF ref_n \\h` 字段。
- **不改变任何段落样式、字体、行距与版式**，仅插入字段结构。

### 7.3 注意事项
- REF 字段显示需要更新域（`F9`）。
- 若参考文献编号顺序变化，应重新运行脚本或更新编号后再更新域。
