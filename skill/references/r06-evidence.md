# r06 案例与数据(证据准备)

对应流水线步骤 6。**"无数据,不动笔"**——产出 `output/work/案例与数据文档.md`,为逐章写作备好可核验的证据链。开始前加载 `output/work/prompt.md`。

## 输入

`output/work/prompt.md`、`需求单.md`、`论文大纲.md`、`文献详细列表.md`、`文献综述.md`;系统先行项目加:`系统需求与技术方案.md`、`work/<系统交付目录>/docs/测试报告.md`、`output/work/data/*`(系统真实导出数据);以及 `input/` 中用户提供的原始数据(问卷、日志、实验记录等)。

## 流程

### 1) 资源盘点(真实数据优先)
- 先扫 `input/` 与系统交付产物:有真实证据(实验数据、运行日志、调研问卷、案例素材、系统导出)→ 清洗标准化,直接使用;
- 系统先行项目:测试数据、性能数据、截图**必须来自真实运行**,已在 r04 沉淀,此处整理归档。

### 2) 生成数据需求清单
按大纲逐节列:章节/小节 → 数据类型 → 关键字段 → 预期呈现形式(图/表/文字)→ 作用;标注三态:**已有可用 / 需补齐 / 需索要**。

### 3) 补齐(仅对"需补齐")
- 允许用"假设/推测/测试"方式形成**待核实草案**,条件:符合领域客观规律(理工:响应有延迟、误差近正态;社科:符合统计常识)、前后参数闭环自洽、能支撑图表;
- **必须在 `案例与数据文档.md` 中逐条标注 `[待核实]`**(含:所在章节/表格、当前值、建议替换方式)。标注只存在于本过程文档与交付摘要,**严禁写入论文正文**——正文按正常论文成文,不带任何标记;
- "需索要"项形成清单,写进交付摘要提醒用户补真实材料。
- 结构化草案可借助 `$SKILL/scripts/数据生成工具/generate_data.py`(含问卷/实验/案例/访谈模板)。

### 4) 质量校验
与大纲逐条对齐(每条数据至少支撑一个小节);统一口径、单位、范围、时间尺度;无与主题无关的材料、无虚构来源。

## 输出

`output/work/案例与数据文档.md`(含:数据需求清单、已用真实数据、待核实草案、需索要清单四部分)。

## 约束

严禁编造文献与不可核验的具体事实;不删不改既有文件;待核实数据必须全部进入最终交付摘要;论文正文零标记。
