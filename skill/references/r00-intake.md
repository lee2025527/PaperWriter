# r00 开工三件事:输入问询 → 需求单 → 锁单

覆盖 SKILL.md 阶段①②③④。目标:开工前把信息一次收齐,确认一次,之后不再打扰用户。

## 一、材料扫描(问询前必做)

1. 扫描 `input/` 全部文件与用户对话中已给出的信息。
2. 可运行结构化抽取辅助(可选,材料复杂时):
   ```bash
   python3 "$SKILL/scripts/requirements-analysis/scripts/build_requirements.py" \
     --input-dir input \
     --output-md output/work/客户诉求.md \
     --output-json output/work/客户诉求.json \
     --ocr-mode auto
   ```
3. 汇总:已明确哪些必填项、还缺哪些。

## 二、必填/选填清单

**硬必填(缺了必须问,不能开工):**

| # | 项目 | 缺失时的问法 |
|---|---|---|
| 1 | 论文选题 | "论文题目是什么?还没定的话,告诉我研究方向,我出 3 个备选你挑一个(或说'你定')。" |
| 2 | 总字数 | "总字数要求多少?各章有分配要求吗?(没有我按结构默认分配)" |

**软必填(有则遵守,无则默认并在需求单标注"默认假设"):**

| 项目 | 默认值 |
|---|---|
| 老师/学校要求(章节结构、研究思路、文献数量与年份) | 结构=学科通用五章结构(绪论/相关基础或综述/方法或设计/实现或分析/结论);文献=15 篇、近 5 年为主 |
| 格式模板 | 无模板用学术中文经典排版(宋体/Times New Roman、小四、1.5 倍行距) |
| 语言 | 中文(含中英文摘要) |
| 引用规范 | GB/T 7714-2015 顺序编码制 |

**条件问(只在相关时追加):**
- "论文需要交一个能运行的系统/程序吗?"(决定是否走系统先行分支)
- "有必读文献清单吗?放进 input/ 或直接发我。"
- "有学校的格式模板 docx 吗?"

**问询规则**:一轮批量问完;用户回复后仍缺硬必填 → 一轮补充追问;此后进入自动模式,只有 SKILL.md §6 三种停止条件可以再开口。

## 三、边界(开工前与执行中始终适用)

**适合做**:中文本科毕业论文、硕士课程论文/小论文、文科社科案例与调研类、理工理论/仿真/算法对比类、计算机系统类(系统先行)、课程作业(实验报告/综述作业,走压缩流程:文献→综述→直接成文)。

**不做/做不了(用户要求时明确说明并拒绝或降级)**:
- 不编造文献、数据、实验结果——数据缺口走 [待核验] 草案或停下问人;
- 不代替真实科研环节(实验、田野、临床数据采集),只整理用户已获得的数据;
- 不承诺通过查重/AI 检测,只做风险降低;
- 博士级原创理论创新点需作者提供,本技能只负责按规范写作;
- LaTeX/特定期刊排版模板不支持,交付形态是 Word;
- 交付物定位是**初稿**:内容真实性与学术合规由作者本人负责。

## 四、需求单生成与锁单

用 `$SKILL/templates/需求单模板.md` 生成 `output/work/需求单.md`,必须包含:
1. 基本信息:题目、类型(纯写作/系统先行)、语言、总字数与章节分配;
2. 硬性要求逐条(来自老师/学校,注明出处文件);
3. **默认假设清单**(每一项默认值单独列出,标注"默认,可改");
4. 文献策略(用户清单优先+不足自动补检 / 纯自动检索);
5. 预期交付物清单(初稿 docx、图表包、[系统先行]系统源码、交付摘要);
6. 交付位置:`output/deliver/`。

向用户展示需求单并说明:
> "请核对需求单。无异议回复'确认开跑';要改直接说,我更新后再给你确认一次。"

- 用户确认 → 在需求单末尾追加"已确认锁定(日期)" → 进入流水线步骤 1。
- 用户补充 → 更新需求单 → 再次展示确认 → 锁定。
- 锁单后如需变更,用户主动提出时更新需求单并重新确认,已产出的下游产物按需重做。

## 五、需求单校验(生成后自检)

```bash
python3 "$SKILL/scripts/requirements-analysis/scripts/validate_requirements.py" \
  --requirements output/work/需求单.md \
  --input-dir input \
  --check-contract
```
校验不通过 → 按提示补齐需求单字段后再展示给用户。
