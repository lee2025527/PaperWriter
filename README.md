# PaperWriter

> **装进终端智能体的论文初稿流水线**:把开题材料变成一篇带真实引用、学术图表、格式完整的论文初稿 docx。

[English](./README.en.md) | 中文

**它不是又一个"AI 写作网页"**——它是安装进你已有终端智能体(Claude Code / ZCode / Codex CLI 等)的一个技能(Skill)。你对智能体说一句"写论文",它就按正常写论文的节奏自动推进:查文献 → 写综述 → 定框架 → 逐章写作 → 自动引用 → 自查 → 交付。计算机毕设类项目还能**先把系统真正开发出来,再照着真实运行结果写论文**。

---

## 一、两条工作流

### 工作流 A:纯写作论文(文科/社科/理论/调研类)

```mermaid
flowchart LR
    S([一句话: 写论文]) --> I[问询 + 需求单确认]
    I --> L[文献: 自动检索/用户清单]
    L --> R[文献综述]
    R --> O[论文大纲]
    O --> D[案例与数据]
    D --> P[写作计划]
    P --> W[逐章批次写作<br/>每批机器校验]
    W --> M[合并 + 引用治理]
    M --> Q[质量与字数优化]
    Q --> F[图表工厂<br/>300DPI PNG / DOCX 表]
    F --> E([论文初稿 docx 交付])
```

### 工作流 B:系统先行(计算机毕设/课设:论文 + 可运行系统)

```mermaid
flowchart LR
    S([一句话: 写论文]) --> I[问询 + 需求单确认]
    I --> L[文献] --> R[文献综述]
    R ==> SY1[系统规划<br/>最小可行边界]
    SY1 ==> SY2[一口气开发交付<br/>一键启动/测试/导出真实数据]
    SY2 ==> O[论文大纲]
    O --> D[案例与数据<br/>真实系统数据回流]
    D --> P[写作计划] --> W[逐章批次写作]
    W --> M[合并+引用治理] --> Q[质量优化] --> F[图表工厂]
    F ==> E([论文初稿 docx<br/>+ 系统源码交付])
```

工作流 B 的核心原则来自长期实战:**论文里的系统截图、测试数据、性能数字,必须来自真实运行的系统,严禁"想象结果"**。这也是它和市面"AI 论文生成器"的本质区别。

## 二、功能边界

**✅ 适合做的**

| 题材 | 说明 |
|---|---|
| 本科毕业论文(中文) | 主战场:结构、字数、GB/T 7714 引用全套 |
| 硕士课程论文 / 小论文 | 行文深度按学位档自适应 |
| 文科社科论文 | 案例分析、调研类;真实数据有则用真 |
| 理工科论文 | 理论分析、算法对比、仿真类 |
| **计算机系统类(系统先行)** | 管理系统/平台/小程序/算法演示 + 论文,一条流水线双交付 |
| 课程作业 | 实验报告、课程论文、文献综述作业(压缩流程) |

**❌ 不做 / 做不了的(红线)**

| 红线 | 说明 |
|---|---|
| 不编造文献、数据、实验结果 | 铁律。数据缺口 → 生成标注 `[待核验]` 的草案,或停下来问你要 |
| 不代替真实科研 | 不做实验、田野、临床数据采集;只整理你已获得的数据 |
| 不承诺通过查重/AI 检测 | 只做风险降低(反 AI 腔改写),检测结果因检测器而异 |
| 博士级原创理论 | 能按规范写作,但创新点本身需要作者提供 |
| LaTeX / 特定期刊模板 | 交付形态是 Word(.docx) |
| 交付定位是**初稿** | 内容真实性与学术合规由作者本人负责(见文末使用声明) |

## 三、快速开始(三步)

### 1. 安装技能(一次性)

```bash
git clone https://github.com/lee2025527/PaperWriter.git
cd PaperWriter
./install.sh          # 自动检测 Claude Code / ZCode 并安装
pip install -r requirements.txt
```

### 2. 配置环境(一次性,约 3 分钟)

```bash
cp .env.example 我的论文/.env
# 编辑 .env,填入 SERPAPI_KEY(免费注册 https://serpapi.com,每月100次搜索)
# 可选:填 OPENALEX_EMAIL 提高文献摘要增强速度
python3 skill/scripts/selfcheck.py   # 自检,全绿即配置完成
```

**SERPAPI_KEY 是必配项**:即使你自带文献清单,清单不足时流水线仍会自动补检——迟早要用,不如一开始配好。(没有网络检索环境?见 FAQ。)

### 3. 开工

```bash
cd 我的论文
# 把任务书/要求/文献清单等材料丢进 input/(乱放也行,流水线负责消化)
claude               # 或你使用的终端智能体
```

```
> 写论文
```

接下来全自动:

```
✓ 材料齐 → 展示需求单 → 你回复"确认开跑"        ← 全程唯一必须的人工确认
✓ 文献检索 → 综述 → 大纲 → 数据 → 逐章写作(每批机器校验)
✓ 合并 → 引用对齐 → 字数达标 → 图表 → Word 初稿
✓ 交付摘要:产物清单 + 字数报告 + [待核验]项汇总 + 润色建议
```

中断了?说一句"**继续**",从断点接着跑。整条流水线只有三种情况会停下来问你:**文献补检后仍不足、批次连续失败、系统跑不起来**——其余全部自愈推进。

## 四、需要准备什么材料

**硬必填(缺了会问你,一轮问完):**

1. **论文选题**——有题目直接给;只有方向 → 出 3 个备选你挑一个;
2. **总字数**。

**软必填(有则遵守,无则用默认值并在需求单标注,不阻塞):**

3. 老师/学校要求——章节结构、研究思路、文献数量与年份、格式模板 docx。

**选填(锦上添花):** 必读文献清单(编号+年份格式)、格式模板 docx、数据/问卷/日志材料、对标论文。

## 六、FAQ

**Q: 没有 SerpAPI key 能用吗?**
A:key 是必配项(清单不足时会自动补检)。注册免费,每月 100 次搜索足够一篇论文。完全离线场景:在 `input/` 放足量的文献清单并在需求单确认"不做补检",可跳过检索,但此路径不在默认支持范围。

**Q: 论文里的数据从哪来?会不会是编的?**
A:三层:① 你提供的真实数据优先;② 系统先行项目用真实系统导出数据;③ 都没有时生成符合领域规律的草案,并**逐条标注 `[待核验]`**,交付摘要里汇总提醒你核实替换。绝不伪装成真实数据。

**Q: 能过 AI 检测/查重吗?**
A:不做承诺。流水线内置反 AI 腔写作规则与黑名单词库,只做风险降低。

**Q: 支持英文论文吗?**
A:主线为中文论文(含中英文摘要)。英文化/英文降 AI 率支线在路线图中(见 `skill/references/optional-extras.md`)。

**Q: 都有哪些自动校验?**
A:每批次落盘跑守护校验(字数/完整性)、合并后覆盖校验、引用序号按首次出现重排并一一对应、prompt 结构校验、需求单契约校验、系统先行项目的 P0 回归测试闸门。

## 七、使用声明

PaperWriter 产出的是**论文初稿**,定位为学术写作的工作流辅助工具。使用者应为材料的真实性、引用的合规性以及是否符合所在学校/机构的学术规范负责。请勿用于违反学术诚信要求的用途。
